CONFIDENCIAL — USO INTERNO
Projeto Banco X — Sistema de Consulta de Valor
Infraestrutura cloud-native de alta disponibilidade na AWS
Papel: DevOps Engineer (Junior)
Orientação: Dev Sênior
Fases: 6 etapas
Cloud: AWS + Terraform
Contexto corporativo
O Banco X precisa disponibilizar um sistema interno de consulta de saldo para seus funcionários. O sistema deve ser acessado via CLI segura, escalar automaticamente em picos de demanda, nunca sair do ar, e ter toda consulta auditada. A infraestrutura será provisionada via código, com ambientes isolados de dev e prod, e entregues de forma contínua via pipeline automatizado.
Stack tecnológica
Imagem base
Packer novo
Cria AMI customizada com Docker + agente ECS pré-instalados. Instâncias sobem prontas, sem depender de user_data.
Infraestrutura como código
Terraform
Multi-ambiente dev/prod com módulos reutilizáveis e estado remoto em S3 + DynamoDB.
Compute — API
ECS Fargate novo
Serverless. Sem gerenciar VMs. Escala automática. Ideal para a API de consulta de saldo.
Compute — Workers
ECS EC2 novo
Usa a AMI customizada. Para jobs internos e processamento batch com mais controle.
Aplicação
Python + FastAPI
API leve e moderna. Dois endpoints: /saldo/{conta} e /health para o ALB.
Container
Docker + ECR
Imagem da API versionada e armazenada no registry privado da AWS.
Banco de dados
DynamoDB
Serverless, escala automático, tabelas isoladas por ambiente. Usado por fintechs reais.
Acesso seguro
SSM Session Manager
Sem porta 22 aberta. Sem chave .pem. Acesso auditado no CloudWatch. Padrão bancário.
Segredos
Secrets Manager novo
Credenciais nunca ficam em variáveis de ambiente ou arquivos. Rotação automática.
CI/CD
GitHub Actions
Pipeline automatizado: build → push ECR → deploy ECS. Trigger no push para main.
Observabilidade
CloudWatch
Logs de auditoria de cada consulta + métricas + alertas de disponibilidade.
Interface do funcionário
CLI Python + SSM Tunnel
Funcionário roda script local. Túnel SSM estabelece conexão segura. Exibe saldo no terminal.
