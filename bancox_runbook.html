Guia completo de restore da infraestrutura após terraform destroy
Projeto: Banco X Fase atual: 04 / 06 Cloud: AWS us-east-1 Criado em: Maio 2026
⚠️ Atenção antes de restaurar

Execute os passos na ordem apresentada. A AMI já existe na conta AWS (ami-0f3a1a124baad0b82) e não precisa ser recriada com Packer, a menos que tenha sido desregistrada. Após o terraform apply, os dados do DynamoDB precisam ser reinseridos manualmente (Passo 5).

00
Verificações iniciais
Confirmar que o ambiente local está pronto antes de qualquer comando
Verificar ferramentas instaladas
# Versões esperadas: Packer v1.11+, Terraform v1.x, AWS CLI v2, Docker
packer version
terraform version
aws --version
docker --version
session-manager-plugin --version
Verificar credenciais AWS
aws sts get-caller-identity
Deve retornar o Account ID 905542450009. Se não retornar, configure com aws configure.
Verificar se a AMI ainda existe
aws ec2 describe-images \
  --image-ids ami-0f3a1a124baad0b82 \
  --query 'Images[0].{Nome:Name,Estado:State}' \
  --output table
Se Estado = available, pule o Passo 01. Se não retornar nada, a AMI foi deletada e precisa ser recriada.
01
AMI com Packer (somente se necessário)
Recriar a AMI base caso ela tenha sido desregistrada

⚡ Na maioria dos casos pule este passo. O terraform destroy não apaga a AMI. Ela só precisa ser recriada se você a deletou manualmente no console AWS.

Navegar para a pasta do Packer
cd /mnt/e/DEVOPS\ GUIADO/BANCO\ X/packer
Inicializar e validar o template
packer init .
packer validate .
Fazer o build da AMI (~5-10 minutos)
packer build ami.pkr.hcl
Ao final anote o novo AMI ID gerado e atualize o arquivo dev/main.tf no bloco do módulo ECS: ami_id = "ami-XXXXXXXXXXXXXXXXX"
Confirmar AMI disponível
aws ec2 describe-images \
  --image-ids <novo-ami-id> \
  --query 'Images[0].{Nome:Name,Estado:State,Criada:CreationDate}' \
  --output table
02
Terraform apply — infraestrutura base
VPC, subnets, ALB, ECS cluster, ECR, DynamoDB
Navegar para o ambiente dev
cd /mnt/e/DEVOPS\ GUIADO/BANCO\ X/dev
Inicializar o Terraform
terraform init
Revisar o plano
terraform plan
Aplicar a infraestrutura (~5-8 minutos)
terraform apply
Confirme com yes quando solicitado. Anote os outputs ao final — especialmente o ALB DNS e ECR URL que mudam a cada apply.
Anotar os outputs gerados
terraform output
03
Populate do DynamoDB
Reinserir os dados de contas bancárias de teste

⚡ O terraform destroy apaga e recria a tabela DynamoDB, então os dados precisam ser reinseridos após cada apply.

Inserir conta — André Leão
aws dynamodb put-item \
  --table-name bancox-dev-contas \
  --item '{"conta_id": {"S": "12345-6"}, "titular": {"S": "Andre Leao"}, "saldo": {"N": "4750.00"}, "agencia": {"S": "0001"}}'
Inserir conta — Maria Silva

Inserir conta — João Souza

Confirmar dados inseridos
aws dynamodb scan \
  --table-name bancox-dev-contas \
  --query 'Items[*].{Conta:conta_id.S,Titular:titular.S,Saldo:saldo.N}' \
  --output table
04
Build e push da imagem Docker
Recompilar a imagem da API e enviar para o ECR
Navegar para a pasta da API
cd /mnt/e/DEVOPS\ GUIADO/BANCO\ X/app/api
Autenticar Docker no ECR
⚠️ A URL do ECR muda a cada apply. Use a URL do output do terraform: terraform output ecr_repository_url
aws ecr get-login-password --region us-east-1 | \
  docker login --username AWS --password-stdin \
  905542450009.dkr.ecr.us-east-1.amazonaws.com
Build da imagem
docker build -t bancox-dev-api .
Tag e push para o ECR
Substitua a URL pelo valor atual do output ecr_repository_url
# Substitua pela URL atual do ECR (terraform output ecr_repository_url)
ECR_URL=$(cd /mnt/e/DEVOPS\ GUIADO/BANCO\ X/dev && terraform output -raw ecr_repository_url)

docker tag bancox-dev-api:latest $ECR_URL:latest
docker push $ECR_URL:latest
05
Deploy ECS e validação da API
Forçar deploy do serviço e validar endpoints
Forçar novo deployment do serviço Fargate
aws ecs update-service \
  --cluster bancox-dev \
  --service bancox-dev-api \
  --force-new-deployment
Aguardar tasks subirem (~60 segundos) e verificar
aws ecs list-tasks \
  --cluster bancox-dev \
  --query 'taskArns' \
  --output table
Devem aparecer 2 tasks. Se a lista estiver vazia aguarde mais 30 segundos e tente novamente.
Validar health check
Substitua pelo DNS atual: cd dev && terraform output alb_dns_name
# Pegar o DNS atual do ALB
ALB_DNS=$(cd /mnt/e/DEVOPS\ GUIADO/BANCO\ X/dev && terraform output -raw alb_dns_name)

curl http://$ALB_DNS/health
Testar consultas de saldo
curl http://$ALB_DNS/saldo/12345-6
curl http://$ALB_DNS/saldo/98765-4
curl http://$ALB_DNS/saldo/55555-0
Validação completa do cluster
# Cluster ativo
aws ecs describe-clusters \
  --clusters bancox-dev \
  --query 'clusters[0].{Nome:clusterName,Status:status,Tasks:runningTasksCount}' \
  --output table

# ALB ativo
aws elbv2 describe-load-balancers \
  --names bancox-dev-alb \
  --query 'LoadBalancers[0].{Nome:LoadBalancerName,Estado:State.Code}' \
  --output table

# Worker EC2 registrado
aws ecs list-container-instances \
  --cluster bancox-dev \
  --output table
